# 網站驗收 SOP v1

適用於 NXTGO 日曆／賽事頁改版、內容接入、本機驗收及已獲授權部署後檢查。研究採集沿用 [賽事研究 SOP](RACE_RESEARCH_SOP.md)。驗收通過只表示已測項目符合預期，不是擁有人確認稿件或發布批准。

## 1. 固定本輪基準

- 記錄目前 branch／commit、工作目錄未提交修改、目標頁面及授權上限：只查、本機修正、commit／push 或部署。不要自行 pull 最新 main 取代使用者指定版本。
- 從 CMS／已有交接恢復賽事 ID、資料屆次／組別、proposal 與網站稿 ID／版本、評分版本、已確認與待覆核狀態。沒有可查的確認紀錄就留未知；不可代擁有人產生批准。
- 區分稿件屆次與承載頁年份：目前港珠澳 2025 稿位於 2026 賽事頁、香港全馬 2025 稿位於 2027 賽事頁；必須保留往屆提示。兩者評分依次為賽道／大會／補給：3／4／3、2／未評／未評，沒有總分。
- 先確認現有預覽是否仍可用，依終端回傳網址開啟，不假設連接埠；避免同時啟動多套相同服務。正式建置用獨立乾淨 checkout，避免與正在運行的開發預覽共用 `.next`。

## 2. 內容核對指令

Node 24+，於 repo 根目錄執行：

```sh
# 預設核對現有 out；不會暗中建置，須確保輸出來自本輪版本
npm run check:content
npm run check:content -- --directory /absolute/path/to/out

# 核對本機 HTTP 實際回應（先啟動預覽）
npm run check:content -- --base-url http://127.0.0.1:3000
```

目前覆蓋 `selectedExperiences` 綁定的兩場 2025 已確認稿。從現有公開 JSON 與完整 payload hash 驗證版本，不讀私人 CMS／原文，不產生批准。核對五主題次序與全文、每題來源次序、未知及限制、三個維度的分數位置、完整評語／依據／適用範圍、規則版本及公開狀態標示。未評不能改為 0；不得為了讓檢查通過而改基準 hash 或已確認稿。

成功回傳 exit 0，任一頁失敗回傳非 0；輸出不包含原文摘錄或私人路徑內容。工具只讀，不啟動服務、建置、寫檔、接受 proposal 或部署。HTTP 模式拒絕轉址、非 200、登入頁及憑證 URL；若網站需要登入，改用已登入瀏覽器核對並記錄工具限制，不改網站權限、不把密碼／token 填進指令。新增賽事須先完成既有人工確認與公開接入，再擴充正式綁定；不自動採用任意 CMS 草稿。

這不是全站內容／來源真偽驗證，也不能證明文字在手機可見、連結目的地可讀或所有私人檔案已排除。RMAC 沿用既有檢查；`npm run check:export` 會同時檢查 RMAC、兩場稿件、私檔排除及頁面隔離。不要把舊 `out` 成功冒充最新頁面通過。

## 3. 手機瀏覽器驗收

用現有可用瀏覽器控制工具操作。尺寸模擬不等於實體 iPhone／Android 測試；工具不可用時記為未測，不宣稱通過。

| 尺寸 | 需要檢查 |
| --- | --- |
| 390 × 844 | 完整流程：顯示、搜尋、篩選、排序及相關賽事內容 |
| 320 × 568 | 窄屏壓力：頁面橫向溢出、長賽名、搜尋／排序、篩選面板及底部按鈕 |
| 844 × 390 | 橫向：開啟篩選後轉向，確認面板／遮罩關閉、頁面可操作及沒有橫向溢出 |

有特定受影響尺寸再補測，不在每個尺寸重跑全部流程。檢查完恢復臨時 viewport 設定，保留使用者需要的本機預覽。

390px 的最小完整流程：

1. 頁首、卡片、長名稱、日期、分數／未知及操作按鈕可讀；沒有內容遮擋或頁面橫向捲動。
2. 中文賽名搜尋、清空、無結果與恢復；核對實際名稱及場數，不只看 URL。
3. 篩選開關、日期範圍、地點＋距離組合、套用、重置、報名狀態及無結果。用現有資料推導期望結果，不寫死會隨時間改變的場數。
4. 切換比賽日期／報名截止／最近更新，對照實際資料排序。沒有已核實截止日期的項目按現行規則置後；未知不當作已開放。
5. 篩選後重新載入／返回，確認條件及結果還原；多頁資料才查分頁及篩選後頁碼重置。
6. 相關賽事頁：往屆年份、組別、逐項分數／未評、五主題及完整評語可展開，來源與限制保留。

等待可觀察的完成條件（載入提示消失、目標結果／按鈕可見）才讀取場數。React 尚未還原 URL 時，預設列表不是篩選失敗。日期欄位直接 `fill` 後若只改 DOM 值、URL／結果未更新，改用原生分段鍵盤或日期選擇器確認，再判斷產品是否有問題；不能用執行頁面 JS 派發事件當作使用者測試。

## 4. 問題、修正與檢查範圍

- 先保存尺寸、可重現操作、預期／實際結果及截圖，再作最小修正。區分程式缺陷、資料未知與工具限制。
- 確認稿件文字、分數或依據如需變更，先交完整指定修訂稿予擁有人重新確認；一般介面修正授權不涵蓋評論修改。
- 沒有改碼：執行內容核對及必要既有測試，不無故重裝依賴或重跑整套建置。
- 有改碼：跑受影響測試與內容核對，重測重現步驟及鄰近尺寸。涉及正式輸出再執行建置、`npm run check:export`、`npm run test:http`；新的問題才擴大測試。
- 發布前仍須 `npm run check:editorial`，並依 [部署流程](DEPLOYMENT.md) 核對確切 GitHub commit／CI／Sites 來源及靜態包。push、驗收通過、匯出均不是部署批准；只在已有明確發布授權範圍內部署，保持原有存取設定。

## 5. 記錄與交付

每輪紀錄放忽略的 `.editorial-private/site-qa/` 或私人 CMS，不提交截圖、原始留言、憑證、登入資料或待覆核評估。SOP／工具程式／無私人材料的測試可跟 repo 管理。不要把 token、Cookie 放入紀錄或 URL。

私人紀錄用以下欄位即可（這是空白格式，不是確認收據）：

```text
時間／時區、執行版本與工作目錄修改：
目標網址／頁面；實測來源（dev／靜態／正式）：
稿件 ID／屆次／組別／版本；評分版本；確認狀態及可查依據：
授權上限與仍需人工決定事項：
尺寸／操作／期望／實際／結果（通過、失敗、未測、工具受限）：
內容核對指令、輸出來源／版本、exit code：
缺陷與最小修正、重測／回歸結果、私人截圖位置：
限制（尺寸模擬／實體機、登入或未讀來源等）：
僅在實際部署後：GitHub commit、Sites source commit／version／deployment ID、正式網址及核對結果：
```

交付簡述發現、修正或無需修正、已測範圍與未測限制、內容是否保持、預覽網址及實際有沒有部署。不因自動檢查成功宣稱人手／法律審核完成。
