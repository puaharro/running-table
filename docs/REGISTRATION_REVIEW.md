# 報名資料自動覆核

賽事研究材料庫的「需要處理 → 報名資料自動覆核」顯示現有賽事、組別和報名渠道的覆核結果。共用一個官方網址的渠道每輪只讀取該網址一次。同一渠道的待查欄位集中顯示。面板沿用賽事及年份篩選。

## 啟動七日試行

1. 在本機 repo 執行 `npm run review:registration -- --start`，啟動試行和跑第一輪。試行期間重跑這個指令會沿用同一結束時間，並只查到期來源。需要立即重查本輪全部來源時執行 `npm run review:registration -- --force`，沿用原有試行結束時間。
2. 讓本機排程每小時執行 `npm run review:registration`。需要前景執行時，可用 `npm run review:registration -- --watch`。網站及 CMS 伺服器毋須一直運行。電腦須能執行排程和連上官方來源。
3. 用 `npm run content:manage` 開啟賽事研究材料庫，前往 `/materials#registration-review`。到期後查看試行紀錄，抽查官方原頁並記下重要變更漏報數量。比較自動記錄的相同欄位、須人手處理的欄位及抽查漏報，再決定是否擴大覆核規則及來源。

距開放或截止 48 小時內每 6 小時覆核，普通來源每 24 小時覆核。同渠道同欄位連續兩次未獲明確依據時延至 48 小時，臨近開放或截止的渠道維持優先。已完賽賽事退出例行覆核。已知截止的一般渠道只補查欠缺的費用，試行另外保留 Garmin 標準費作對照。優先／精英渠道在賽前仍保留資格、申請及付款紀錄供覆核。已核實的慈善／旅遊連結每七日重查，待查連結按普通來源間距重試。

## 渠道覆核標準

- 一般報名逐欄核對當屆及組別的入口、開放、申請截止、標準費和名額狀態。
- 優先／精英報名再核對門檻、認可成績期及證明要求。有獨立結果公布或付款期限時，逐欄記錄。僅能核對部分資格時，完整資格欄保留待查。
- 慈善、住宿及旅遊渠道只核對當屆賽事的官方或指定夥伴詳情連結。伙伴來源須有大會指定依據，頁面亦要顯示適用屆次。共用同一連結的組別合併顯示。欠連結、讀取失敗或無法確認屆次及指定關係時列入連結待辦。

大會已確認全組額滿，而且現行各組報名狀態都有同一份官方依據時，停止例行欄位覆核。單組賽事可憑該組公告完成。CMS 保留公告連結及核對時間。個別組別有官方額滿依據時，停止該組的例行報名欄位覆核，保留公告及核對時間。其他組別繼續覆核。慈善／旅遊渠道在取得有來源的額滿或截止證據後退出例行連結覆核。CMS 保留渠道、官方連結及已知截止日期。

## 處理結果

先按賽事集中查當屆官方來源，從同一頁核對所有適用組別。CMS 待查按賽事展開。名額狀態已有明確開放依據的渠道，停止追查歷史開放時間。官方明列「額滿即止」而沒有固定截止日期時，記下該條件。若官方同時公布固定日期，保留日期並按先到先得理解實際截止。

- 官方值相同時自動保存欄位、原文、來源及核實時間。
- 官方值有差異時顯示原值、建議值和原句。營運者可批准或拒絕個別欄位。批准保存為私人 CMS 紀錄，接入賽事資料及發布沿用[現有流程](CONTENT_OPERATIONS.md#網站交付與驗收)。接入前確認現行值和官方依據仍與批准紀錄相符。
- 截止時間、標準費用和名額各自記錄。只看到「立即報名」、網頁要求登入、讀取失敗、版型改動、資料互相矛盾，或未能對應屆別及組別時，保留待查並記下嘗試時間。先前證據和核實時間仍保留。

自動覆核使用本機私人內容資料庫。試行原文、判斷、時間及人工決定可隨 CMS 私人備份保存。公開網站資料仍由 `src/data/catalog.json` 提供。CMS 的費用或截止核實時間不可當作已核實即時名額，網站的 72 小時報名狀態檢查仍按公開資料的狀態核實時間計算。

目前有渣馬優先報名日程、少年跑費用及截止、海洋公園截止、大埔半馬逐組費用及半馬額滿公告、Garmin 個人組標準費、美津濃和糖尿聯會全組額滿的辨識規則。其他來源或欄位可出現在待查，供營運者開原頁續查。新增規則先用官方當屆樣本驗證，並覆核分組、早鳥／標準收費、公告時間及適用範圍。
