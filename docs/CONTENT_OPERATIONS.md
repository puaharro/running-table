# 內容與資料維護

## 工作流程

收集官方公告 → 記錄來源 → 整理草稿 → 核實重要欄位 → 編輯審閱 → 資料檢查與建置 → 發布。開發期用 Git 分支及 Pull Request 留低修改；repo 已連接 GitHub；本地未推送修改須另行發布。

優先覆核即將截止、開放報名、延期取消及讀者更正。更新頻率按實際營運人手決定，原型未設定自動排程。

## 每場賽事清單

- 正確年份、主辦方、活動名、路跑類別。
- 各組日期、距離、資格、費用、報名起止與狀態。
- 起點、終點、交通及集合安排；未知標示待核實；只有官方明確表示未公布才使用該描述。
- 官方來源、核實時間、變更說明。
- 原創摘要及選賽重點，唔直接複製第三方文章或未授權圖片。
- 報名前再次核對官方入口；網站唔承諾即時名額。

## 指南編輯原則

寫清楚要幫讀者完成咩決定，提供可操作比較方法。涉及賽事條款逐場查證；唔一概而論。作者／編輯身份須真實，無實地經驗就唔冒充實測。文章互相連結相關賽事，賽事頁亦推薦適當指南。

目前三篇原創初稿：第一場 10K 選賽、報名前清單、半馬比較。正式發布前覆核語言、來源及需要補充嘅細節。

## 歷屆與更正

保留每屆獨立頁面，標明已完成；新一屆同舊一屆互相連結。重大改期、取消等消息放當眼位置。

目前測試版已有資料更正表單，可準備 GitHub Issues 公開回報；填表不會自動提交。設定公開聯絡電郵後改用電郵入口。公開營運前補上真實營運者身份、可用聯絡渠道、處理回報方式及所需私隱文件，唔使用虛構聯絡資料。

## AdSense

先完成有用、原創、可公開閱讀嘅內容，先申請及接入。廣告同報名入口清楚區分，覆核手機閱讀、版位跳動及誤點問題。目前無任何廣告程式；版位預覽需明確開啟開發設定，唔代表已獲審批。

## v0.2 資料位置與待核實清單

真實資料放喺 src/data/catalog.json；按 DATA_MODEL.md 填來源、核實時間、渠道及 publication。已知狀態必須有報名欄位佐證。來源表見 SOURCE_LEDGER.md；執行 npm run review:data 睇按當時計算嘅待核對組別。

超過 72 小時嘅狀態會顯示待核實，唔會自動重新查詢官方。重新建置唔可以將舊 checkedAt 改成新日期；只有真實重新核對先更新。
