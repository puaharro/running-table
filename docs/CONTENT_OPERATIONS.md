# 內容與資料維護

## 工作流程

收集官方公告 → 記錄來源 → 整理草稿 → 核實重要欄位 → 編輯審閱 → 資料檢查與建置 → 發布。開發期用 Git 分支及 Pull Request 留低修改；repo 已連接 GitHub；本地未推送修改須另行發布。

優先覆核即將截止、開放報名、延期取消及讀者更正。更新頻率按實際營運人手決定，報名資料自動覆核按下方私人 CMS 試行流程運作。

## 每輪更新流程

已收錄賽事先查看 CMS 待辦的[報名資料自動覆核](REGISTRATION_REVIEW.md)。自動記錄有官方依據的相同值，變更由營運者逐欄批准。一般及優先／精英渠道逐欄核實，慈善及旅遊渠道只核對當屆官方或指定夥伴連結。未獲明確依據的項目留待補查。

營運者指定範圍時按該範圍執行。例行更新依次處理四項，任何一項沒有發現也寫明。

| 次序                    | 操作                                                                                                                                  | CMS 交付                                                                           |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 1. 發現新賽事           | 查田總、主辦方與官方報名平台的香港路跑公告。以賽名別稱、年份、比賽日期及主辦方對照公開目錄與私人建議，避免重複收錄。                  | 每屆一份新增建議，附官方來源、組別、日期和地點。費用或即時名額未確認時保留待核實。 |
| 2. 更新已收錄資料       | 先處理改期、取消及地點變動，再查七日內截止、即將開放，以及資料已過期的渠道。用 `npm run review:data` 整理待核對項目，再開官方頁覆核。 | 逐欄寫明舊值、建議新值、來源和查閱時間。僅更新確實核對的時間戳。                   |
| 3. 更新最新一屆跑手留言 | 選已舉行、最新屆次尚未有完整心得或有新材料的賽事。核對賽事及組別，按[研究 SOP](RACE_RESEARCH_SOP.md) 查原文並保留觀察限制。           | 同一賽事及屆次整合成一份建議。保留正反觀察、來源、缺口及待登入項目，交營運者確認。 |
| 4. 更新首頁最新消息     | 用今輪已核實資料檢查十四日內報名截止及最近三十日核對的官方路線圖。                                                                    | 列出預計新增、更新或移除的消息，附組別、日期及對應詳情頁。                         |

跑手留言可以在賽後一至三日先收一輪，一星期後補查較長的賽記或影片。來源不足時，先標明待補查及原因。主辦方公布的更改可獨立處理，以免延誤重要通知。

每輪交付一份短摘要，列出新增候選、已覆核改動、當屆留言草稿、首頁消息及待處理項目。官方資料和跑手觀察分別引用相應來源。已確認稿件按現有發布程序處理。

## 首頁最新消息

首頁由 `src/lib/home-race-news.ts` 讀取賽事表使用的資料，自動生成中英文消息。以香港時間預覽，核對以下項目。

- **報名截止。** 核對官方報名已開放、截止仍有效、距今最多十四日，以及消息顯示的組別範圍。同步更正受影響渠道的狀態與期限。
- **官方路線圖。** 核對當屆官方連結，將來源列於賽事資料並標記 `courseMap`。消息只顯示最近三十日內核對的路線圖。只有實際重查才更新核實時間。
- **顯示及退場。** 上限四則。核對中英文首頁、截止日期、消息排序與連到報名組別或官方來源的錨點。核對已截止、取消或過期的消息退場。新增收錄及賽後留言各自更新賽事表與詳情頁。首頁今輪無變動時在摘要寫明。

## 網站交付與驗收

1. **賽事表。** 把已確認的新增賽事及欄位差異寫入 `src/data/catalog.json`，按資料模型更新組別、報名渠道、來源及核實時間。建置後核對表格搜尋結果、連結和賽事詳情。未有當屆跑手材料的賽事可先交付賽事表。
2. **跑手留言。** 確認已完賽及有可引用的當屆材料後，從 CMS 按賽道、補給、寄存、交通、大會安排準備完整網站稿。每題包含正文、觀察限制及來源。沿用[通用 CMS 接入流程](COMMENT_RESEARCH.md#通用已確認-cms-內容接入公開-runtime)，按已批准的記錄雜湊選入對應賽事頁。核對賽事 ID、屆次及組別。來源不足的場次，在私人紀錄留下原因和下次查閱日。
3. **驗收。** 執行 `npm run check:data`、`npm run build`、`npm run check:export`、`npm run test:http`。開啟改動的詳情頁，按[港珠澳半馬 2025 版型](../skills/nxtgo-site-qa/SKILL.md#跑手分享年份切換)核對主題展開、全文、觀察限制及來源。同組別多屆要核對年份切換及舊連結。另核對表格欄位、中英文首頁消息與對應連結。獲授權部署後，以同一組網址核對正式網站。

新增賽事首次寫入賽事表時，在 `changes` 首筆記下香港日期，其後的核實與補資料追加在後。中英文賽事列表以首筆日期計算 **NEW**，從當日開始顯示 14 個香港曆日，只適用於尚未完結的已排期賽事。驗收時抽查新賽事及同輪更新過的舊賽事。

在私人工作區保留每輪摘要，記錄來源覆蓋、查閱日期、五類結果（新增、資料變更、留言、首頁消息、待辦）、相關頁面及目前進度。下輪先讀上一輪待辦，按原流程次序處理，並記明仍未能查閱的來源。

## 每場賽事清單

- 正確年份、主辦方、活動名、路跑類別。
- 各組日期、距離、資格、費用、報名起止與狀態。
- 起點、終點、交通及集合安排；未知標示待核實；只有官方明確表示未公布才使用該描述。
- 官方來源、核實時間、變更說明。
- 原創摘要及選賽重點，唔直接複製第三方文章或未授權圖片。
- 報名前再次核對官方入口；網站唔承諾即時名額。

## 指南編輯原則

寫清楚要幫讀者完成咩決定，提供可操作比較方法。涉及賽事條款逐場查證；唔一概而論。作者／編輯身份須真實，無實地經驗就唔冒充實測。文章互相連結相關賽事，賽事頁亦推薦適當指南。

目前三篇原創初稿：第一場 10K 選賽、報名前清單、半馬比較。正式發布前覆核語言、來源及需要補充嘅細節。

## 歷屆與更正

保留每屆獨立頁面，標明已完成；新一屆同舊一屆互相連結。重大改期、取消等消息放當眼位置。

目前測試版已有資料更正表單，可準備 GitHub Issues 公開回報；填表不會自動提交。設定公開聯絡電郵後改用電郵入口。公開營運前補上真實營運者身份、可用聯絡渠道、處理回報方式及所需私隱文件，唔使用虛構聯絡資料。

## AdSense

先完成有用、原創、可公開閱讀嘅內容，先申請及接入。廣告同報名入口清楚區分，覆核手機閱讀、版位跳動及誤點問題。目前無任何廣告程式；版位預覽需明確開啟開發設定，唔代表已獲審批。

## v0.2 資料位置與待核實清單

真實資料放喺 src/data/catalog.json；按 DATA_MODEL.md 填來源、核實時間、渠道及 publication。已知狀態必須有報名欄位佐證。來源表見 SOURCE_LEDGER.md；執行 npm run review:data 睇按當時計算嘅待核對組別。

公開網站會將超過 72 小時嘅狀態顯示為待核實。私人 CMS 試行會另行巡查官方來源。重新建置唔可以將舊 checkedAt 改成新日期；只有真實重新核對先更新。
