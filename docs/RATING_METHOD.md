# 組別比較規則：開發者維護方式

目前啟用 `2026-10-30-v2`，發布者為 NXTGO 編輯。規則設定在 `src/lib/rating-policy.ts`，計算在 `src/lib/group-ratings.ts`；網站準則由同一設定產生，避免文字及程式門檻不一致。

## 本版範圍

- 時限寬鬆度只看已核對總時限除以距離，使用原始數值分級，顯示時換算分秒；資格、年齡及距離不再扣分或設上限。
- 距離負荷只比較距離；沿用5 km、21.1 km界線，不宣稱為完整賽道難度。
- 集合交通要求使用事實標籤，不作1–5分好壞判斷；需接駁不代表不便利，未計讀者住所及實際交通路程。
- 參加資格獨立顯示，少年時限不是成人推薦；不同組別或渠道時限未整合前不猜出單一時限。
- 資料不足顯示未評，不計零分，不設總分或整體排名。未評有理由，已用事實有來源及原核對日期。

## 修改準則

1. 先寫清楚要衡量的概念、所需事實及適用組別。事實來源與編輯判斷分開，既有核對日期不能因改規則而更新。
2. 修改集中設定的門檻、標籤及說明；門檻維持排序、覆蓋所有有效輸入。同步提升規則版本，記錄具體原因，勿把舊規則分數當成新結果。
3. 更新邊界、同時限不同距離、資格獨立、缺資料及組別隔離測試；執行全套測試、正式建置、匯出與HTTP檢查，再查手機顯示。
4. 部署前用熟悉的不同賽事檢視是否出現反直覺結果，收集跑手／教練回饋；不要宣稱已經科學驗證。

## 完整難度尚未啟用

目前完整難度一律顯示未評。不能直接把以上三項相加或只改標題就稱為完整難度。

如日後要推出，應另訂路跑及越野的適用準則、完整且有組別依據的爬升／下降、路面及技術要求、途中截點與補給／環境資料，避免把距離及完成時間重複加權。缺少必要資料時仍不計完整難度；加入新資料模型、來源驗證、測試及校準後才啟用。本版不補查或估算未能驗證的賽事資料。
