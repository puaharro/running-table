# 評級發布、材料保存與投訴處理

## 現況與限制

- 本版仍是靜態網站：筆記在瀏覽器儲存，回報表格準備電郵，不是後台收件或工單系統。只有寄件人自行寄出，郵箱實際收到後，營運者才可記錄「已收到」。
- 公開評級聯絡電郵為使用者指定的 phonesaverltd@gmail.com。不要代寄、登入郵箱、聯絡大會、聘請律師或投保；這些需要使用者另行授權。
- 發布檢查提供版本綁定，並非數碼簽署、身份認證或法律審核。它能阻止未有確認紀錄／改稿沿用舊確認的意外發布，不能阻止有repo寫入權的人捏造紀錄。AGENTS.md禁止代理代替真人批准。

## 私密材料

本機 `.editorial-private/` 已加入gitignore，不得從src或public匯入，也不包含於Git archive及網站部署。這是本機資料夾，沒有雲端備份；營運者需另作適當私密備份及存取管理。

- materials/：原始訪談、日期／批次、圖片、來源及觀察限制。保留原話，與編輯判斷分開。
- `*-pending.json`：待確認的完整候選評論，status=pending-confirmation，保留提出的分數，但不作正式公開評分。
- `*-confirmation.md`：供營運者閱讀及確認的具體版本。
- cases/：投訴電郵及處理紀錄，採案件代號；公開頁只放必要摘要。

資料曾在舊版本或Git歷史公開，移入私密資料夾不會追溯消除那些副本。本次不改寫Git歷史，不聲稱已將過往內容完全刪除。

## 發布一份評論

1. 整理公開候選稿：年份、組別、參賽者範圍、材料摘要、每項分數及短評、優點／問題、適合對象、利益關係。原始私人資料不放入候選稿。
2. 指定revision正整數及reviewedAt。新增或修改可公開的大會回應、changes、材料或規則，均屬改稿。
3. 執行 `publicationDigest`（scripts/editorial-publication.mjs）計算完整稿件的SHA-256。控制狀態及approval本身不在內容雜湊內，其他欄位均納入；待確認轉為已發布不改變所批准內容。
4. 讓營運者閱讀完整識別版本，明確確認分數、字眼、材料及範圍。一般「更新／合併／部署」不能當作對評論的確認。
5. **只有收到真人明確確認後**，才可建立approval：by、at、reference（可追溯的私密批准紀錄代號）、revision、contentHash及四項confirmed=true。不要將原始批准對話、個人電郵或檔案路徑放入公開資料。
6. 1–2分或敏感字眼會觸發額外覆核紀錄riskReview（by/reference/note）。提示可能誤報或漏報；涉及欺詐、安全、違法等具體指控，應視情況交律師，不能把提示通過寫成法律批准。
7. 將已確認公開稿放進src/data/editorial-reviews.json，status=published。`npm run check:editorial`會驗證雜湊及確認；`npm run build`先自動執行此檢查，再執行內容驗證／TypeScript／建置。修改內容會阻擋發布，須重新確認。
8. 公開評論顯示確認人、時間及稿件版本；changes記修改摘要，organizerResponses記經核實且可公開的回應。回應亦包含在確認內容內。

## 處理投訴及大會回應

- 實際收到郵件後，在本機cases/建立紀錄：案件代號、收到時間、評論／版本、爭議句子、材料位置、寄件人聯絡方法、狀態及處理日誌。
- 狀態可採：已收到→核實中→需要補充→已更正／已回應／暫停展示→結案。不要為尚未收到的表格建立假案件或收件時間。
- 確認收到不代表承認內容錯誤。核對原話、時段、組別、反證及可公開範圍；必要時詢問原作者、大會或法律顧問。
- 重大爭議可暫停展示，保存原始版本及材料。更正後更新評論revision，重新確認，公開必要修改摘要，避免重複傳播已撤回指控。
- 大會回應先核實寄件來源及公開範圍。只發布獲准公開的回應內容，不發布私人聯絡資料；沒有回應就不虛構。
- 收到律師信或法院文件，記錄期限並盡快交香港律師處理；不要自行承認責任或簽承諾。保留原始材料，不自行銷毀紀錄。

## 法律及保險待辦

本版沒有完成律師審閱或投保，不可宣稱有法律保障或保險承保。營運者可準備：網站定位、營運者、收入／贊助模式、評分準則、示例、材料及投訴流程，向香港傳媒／誹謗法律師要求審閱範圍及報價。

向經紀索取媒體責任保險報價時，要求書面列明受保人士、網上評分及AI輔助內容、抗辯費／自付額、地域／司法管轄、過往內容及已知爭議、其他除外責任與索償通知規則。未核對保單前不要寫「已受保」。
